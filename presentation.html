Vue architecture

Architecture réelle du template et de ses flux Hub

Cette vue est isolée dans un onglet dédié pour donner plus de largeur au schéma. Les flux frontend, backend, proxy Hub, M2M, messages, SSE et données locales sont séparés pour éviter le chevauchement des labels.

Flux 1

Navigateur vers frontend local

L'utilisateur arrive sur l'application servie localement. L'interface porte la configuration runtime, le token utilisateur et la couche visuelle de messagerie.

Flux 2

Frontend vers Hub via le proxy /hub

Les échanges navigateur sensibles au contexte HTTPS, comme les messages utilisateur et le SSE, passent par /hub pour éviter les problèmes de mixed content.

Flux 3

Backend vers Hub en direct

Le backend utilise le service account de l'application pour la découverte de services, les appels M2M, l'envoi de messages et la synchronisation de sauvegardes.

Flux 4

Backend vers données locales

L'API conserve la maîtrise de PostgreSQL et des fichiers uploadés. Le mécanisme de backup sait découvrir les tables et reconstruire l'état applicatif.
